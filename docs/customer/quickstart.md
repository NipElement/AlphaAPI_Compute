# ARISE B300 — 客户快速上手

> 面向租户用户。本文只写**今天真实可用**的路径;标注「即将」的是已排期、尚未交付的。

## 1. 登录

控制台地址由 ARISE 提供(HTTPS)。账号密码由 ARISE 开通时一次性告知。**改密码**:
`POST /auth/password`(请求体 `{"current": "...", "new": "..."}`,新密码 ≥ 12 位;成功后所有会话失效,重新登录)——
控制台右上角用户菜单里也有入口。会话 12 小时,登录连续失败会被暂时锁定(按来源 IP 严格、
按账号宽松),稍等再试即可。

## 2. 你能看到什么

左侧「工作台」:概览 · 开发机 · 自定义任务(gang)· 在线服务 · 存储卷 · 镜像仓库 ·
资源与队列。你的账号被锁定在你的命名空间;其它租户对你不可见,反之亦然——这是在
API 层强制的,不是界面隐藏。

## 3. 开一台开发机(可 SSH)

创建时填入你的 **SSH 公钥**(`~/.ssh/id_ed25519.pub` 的那一行),选择规格:

| 规格 | 内容 |
|---|---|
| `gpu.1` | 1× B300 (288 GB HBM) + 31 vCPU + 248 GiB(8 片正好铺满一台机器) |
| `gpu.2` / `gpu.4` | 1/4、半节点 |
| `gpu.8` | 整节点 DGX B300(8× B300,NVLink 全互联) |
| `cpu.small` / `cpu.large` / `cpu.custom` | 无 GPU;`cpu.custom` 自填 vCPU / GiB |

**GPU 规格需要你名下有已预留(DIRECT)的节点**:整机客户的 GPU 负载只会落在为你预留的节点上;
没有预留时 GPU 任务会一直 Pending(事件里写 `didn't match Pod's node affinity/selector`)。
按需 GPU(共享池)的开通方式见第 5 节;拿不准就问支持。

机器就绪后,「开发机」列表的 **SSH 端点** 列显示 `dev@<name>-ssh.<你的命名空间>.svc:22`。
这是集群内地址;**从公网接入目前由 ARISE 运维为你开通一条转发**(你会拿到 `host:port`),
公网直连地址在排期(决策 D4)。

```bash
ssh dev@<ARISE 提供的接入地址> -p <端口>
# 数据进出:scp / rsync 直接可用
scp -P <端口> ./dataset.tar dev@<地址>:/home/dev/
rsync -e "ssh -p <端口>" -avz ./code/ dev@<地址>:/home/dev/code/
```

机器里:`/home/dev` 与 `/tmp` 可写,`pip install`、`git clone`、`curl` 正常(出向可访问公网;
宿主机/管理网段被围栏拦住);根文件系统只读(安全策略,不是故障)。挂载了存储卷时在 `/data`。
**删除开发机不会删除它的数据卷**(仍占配额):到「存储」页删,或删除时带 `?deleteVolume=true`。

**换公钥不用重建机器**:钥匙泄露或换电脑时,用新公钥调用
`PUT /papi/devmachines/<name>/ssh-key`(请求体 `{"sshPublicKey": "ssh-ed25519 …"}`,控制台"开发机"页也有入口),
1–2 分钟内 sshd 只认新钥匙;`/home/dev` 里的东西不动,已经打开的会话不会被踢。

**注意**:开发机被删除重建时**主机密钥会变化**(SSH 会提示 host key changed),
这是当前行为,持久主机密钥在排期中。

> 「即将」:从公网直接 SSH 的接入地址(目前由 ARISE 运维提供转发);Web 终端。

## 3b. 在线服务

「在线服务」创建的端点 `<name>.<你的命名空间>.svc:80` 在**你自己的命名空间内**可达
(比如从你的开发机 `curl http://<name>:80`)。其它租户访问不到它;从公网访问它
在排期中(与 SSH 公网接入同一决策)。

## 4. 存储

两类存储卷,都以 10 GiB 为步长:

- **arise-shared**:工作区。随卷删除而删除。
- **arise-longterm**:长期。**卷删除后数据保留**,需要 ARISE 运维显式清理——这是
  故意的摩擦,防止误删模型。

配额在「资源与队列」可见。当前存储是节点本地 NVMe:**一个卷只在它所在的那台
机器上可见**;跨机共享文件系统在排期中。

## 5. 计费(按分钟)

- 按需 GPU:每 GPU 每小时 $9.57,**按分钟计**,不足一分钟按一分钟(**每张账单内**如此:一个跨月的区间会在两张账单里各自向上取整,最多多计一分钟 ≈ $0.16/卡,已实测)。
  **计费区间 = 你占着这台机器的 GPU 的时间**:从 pod 被调度起(Kubernetes 的 `status.startTime`)
  到它结束或被删除为止。容器崩溃重启、镜像拉取、初始化容器运行期间**同样计费**——那段时间 GPU
  仍然被你占着,别人拿不到。这也是为什么台账里一个 pod 只有一个区间,而不是每次容器重启一段。
  pod 结束/删除的时刻以平台观测到的最后时间为准(轮询间隔 ≤15 秒,取整方向对你有利)。
  记账基于平台台账(每条记录带哈希链),对账时可逐条给出。
- 整机包月:$52,750 / 月 / DGX B300,按预留天数比例。
- 控制台「用量」页实时显示你的 GPU·小时、当前占用 GPU、存储 GiB·小时与每条分配区间(来自同一份台账);每月账单为 CSV(由 ARISE 发送),附每条计费区间的开始/结束时间与 GPU 数;金额只在账单上(在线支付属决策 D6)。
- 任务一直 Pending 的三种原因:没有为你预留的节点(整机客户)、超配额(事件里有 `exceeded quota` 与用量数字)、请求不合法(创建时就会被拒并说明)。

## 6. 你不能做的(以及为什么)

- 不能把负载钉到某台机器(`nodeName`)或容忍平台污点——这些是隔离围栏。
- 不能用 hostPath / hostNetwork / privileged——根文件系统与宿主机属于平台。
- 不能选队列以外的调度队列——队列表达的是合同权益,不是偏好。

遇到 `Forbidden`,错误信息会写明被哪条策略拒绝、该怎么改。

## 7. 求助

你在平台上的每次操作(创建/删除/换钥匙)都有服务端留痕(网关访问日志 + API 审计日志),需要时可向 ARISE 索取你自己租户的切片;
控制台里的「审计」页是平台运维视角(节点所有权轨迹),租户看不到。报障时附上时间与对象名即可。

## 账单里有什么

- **GPU 时**:每个 pod 从被调度到结束(不是从容器启动到退出——重启不重复计费),按分钟向上取整,`$9.57/卡·时`。
- **整机月费**:预留(DIRECT)节点按自然月天数摊分;该节点上你自己的 pod 的 GPU 行记 `$0`(月费已含)。
- **存储**:每个已绑定的数据卷按 GiB-月列出,**当前价格 $0(30 TB 已含)**——这一行存在是为了让你看见自己占了多少 NVMe。
账单由 append-only 哈希链台账离线复算,同一输入永远得到同一字节;有疑问可以要你自己租户的台账切片自己算。
链的作用是**可核查**:任何一条记录被改、被删、被换序,重算时都会指出是第几条出的问题。
它不是"不可能被改"的保证——防篡改依赖的是链 + ARISE 侧独立留存的链头历史(由监控系统保存,计量进程改不了),
两者对不上即视为账目有争议,按合同条款处理。
