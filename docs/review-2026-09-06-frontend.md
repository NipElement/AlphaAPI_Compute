**不能把此前的结果表述为“前后端全部完成，只等 GPU 上集群”。** 此前虽然有核心集群矩阵、接口和 SSH 验收，仓库没有可重复的浏览器全流程测试。本次实际补测找到了生产数据显示、组件用法、故障恢复和公钥校验问题。修复后仍应称为待生产验收的候选版本。

## 本次实际发现并修复

| 缺陷 | 影响与修复 |

## 仍然不能承诺的事项

1. **生产存储硬限制和数据保障仍是上线条件。** local-path 的 PVC 申请容量不能约束目录实际写入量；Retain 不是异机副本。公开共享存储售卖前需要可验证的硬限制，或收窄为独占节点的明确服务范围。
2. **本地恢复测试不等于离机灾备验收。** 账号、台账、etcd、证书和 SSH 主机密钥需要独立故障域的加密备份、告警，以及按实际备份介质恢复的演练。
3. 真实域名、TLS 签发、客户密钥、生产镜像 digest、防火墙和告警接收端尚需交付与验收。堡垒已经实现和在 kind 验证，生产入口没有因此自动启用。
4. 没有 24–72 小时持续负载、全量并发规模、Firefox/WebKit、完整可访问性或移动设备真机验收。当前主机缺少中文字体；DOM 翻译已验证，中文截图字形不能作为验收依据。
5. 真 GPU 的驱动、CUDA/NCCL/RDMA、拓扑、性能和实际故障恢复需要硬件。计量仍有周期轮询可能漏掉极短任务的边界，平台仍有单头节点/单写入者故障域。

以上限制中有多项与“没有真 GPU”无关。当前证据支持已列出的功能与故障场景通过验证，不能支持“所有可做的测试已经穷尽、可无条件对外上线”。
