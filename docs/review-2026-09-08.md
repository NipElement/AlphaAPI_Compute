## 漏网之鱼（按严重度）

### 1. critical — DIRECT→ARISE 回收的清理门是 check-then-act，节点从不 cordon
上轮审计（`direct-reclaim-sanitization-toctou`）唯一没有验证的 critical，**在 codex 的重构里原样保留**。
`_reconcile_arise` 是四条状态流转里唯一不调用 `_start_drain()` 的：第 3 步跑一次
`run_sanitization()` 记下 HEALTH_CHECK 就返回，第 4 步在**下一个** reconcile（≥10 s 后）
剥污点、解 cordon、写 `owner=ARISE`，中间不复核。而退租客户的节点在这整个窗口里仍然
`owner=DIRECT`、未 cordon、准入允许其 pod 落回来。用桩 harness 复现：HEALTH_CHECK 时租户
pod 为 Running，控制器照样写 READY/ARISE 并发 `ReclaimComplete`——**一台机器两个租户，
OwnerConflict 读到的恰好是 1**。修法两半：进入回收先 cordon（`ReclaimFenced` 事件）；
翻转那一刻重跑 `live_tenant_pods` + GPU 占用，有东西就退回 SANITIZING（`ReclaimRecheckFailed`）。
两条新单测各自证伪（去掉任一半立刻变红）。

**活集群上又抓到第二层**：修完 fence + 复核后在 kind 上真跑这场竞争，等待中的客户 pod 仍然
**绑定到了 worker4**——第 4 步的写入顺序是「剥污点 → 解 cordon → 改标签」，解 cordon 到改标签
之间节点可调度且标签仍是 DIRECT/租户，调度器就在那个缝里把 Pending 的 pod 绑了上去。改成
「改标签（同一个 merge patch 同时清掉 `arise.ai/tenant`）→ 剥污点 → 最后解 cordon」，
第三条单测钉住顺序并证伪；再跑活集群竞争：pod 始终未绑定（`node=''`），回收正常完成。
fence 和复核只保护它们**之前**的写入——写入顺序本身也是不变量的一部分。

### 1b. high — 控制器的事件从来没有落过盘（不是 codex 引入，但 codex 把唯一的线索删了）
`emit_event` 把集群级对象 NodeOwnership 的事件 POST 进 `platform-system`，API server 一律
**422**（`involvedObject.namespace: "" does not match event.namespace`）。从这个函数写下那天起，
集群上 NodeOwnership 事件数是 **0**——跑了几百次交接。隔离 runbook 的第一条命令
（`get events --field-selector involvedObject.name=<node>`）永远返回空，证据里的 `capture_events`
永远抓到空，没有任何用例发现，因为它们全读 `status.conditions`。我上周的版本会打一行 WARN，
没人看；codex 的重写改成 `except Exception: pass`，连那行也没了。修法：集群级对象的事件必须建在
`default`；失败必须记日志并计数（`EventWriteFailed`）；OBS-06 新增「隔离必须留下操作员能查到的事件」
的断言；runbook 改成 `-A`。部署后活集群第一次出现 DrainStarted / DirectAssigned /
ReclaimFenced / ReclaimComplete。

### 2. high — DCGM 抓取任务仍是注释，Day-0 没有任何一步让人去掉注释
`platform/overlays/dgx/monitoring.yaml` 里 `job_name: dcgm-exporter` 整段被注释，注释说
"装好 GPU Operator 后取消注释"；`day0-setup.md` 第 10 步只说创建 dcgm-metrics ConfigMap。

- **开发机 grace 写死 5 秒**：门户 `GRACE_CAP_SECONDS`（= 准入上限，render 门 4c' 校验一致，gate-selftest 多一条突变）与

  PID 1 忽略 SIGTERM 的进程会把每次删除拖满整段 grace，长默认值等于让所有人都慢。
- **privileged 命名空间**：静态扫描发现范围比记录的大——`platform-system`（lab：fake-gpu 插件；dgx：备份 CronJob、node-exporter）
